# AI Tech Video Production

输入已剪好的真实口播视频、可选文案和素材，交付成片，或用户指定的时间线、字幕、可编辑工程。按请求范围完成，不把单项修改扩展成整片重做。

## 输入与职责

- 本技能负责字幕、B-roll、真人布局、重点分镜动效、合成与交付，不承担口播精剪。已剪好的口播保留时长、语序和音画同步；按语义分段是安排覆盖画面，不是删减原片。
- 用户明确素材未剪好时，先读取当前安装的 `video-use/SKILL.md`，由 Video Use 在用户确认精剪策略后完成精剪。交接剪好的口播文件、媒体参数与检查结果；如有字幕或时间戳，应对应剪后时间线。主技能检查交接文件后再开始画面制作，不沿用剪前时间戳。
- 默认输入已剪好，不自动启动精剪；素材状态不明且会影响制作时，只确认是否需要先精剪。Video Use 的范围仅限此次前置精剪，不提前重复添加本技能负责的 B-roll、动效和烧录字幕。工具缺失或精剪受阻时明确告知用户，不把原片当成剪好成品交接。
- 主技能统一整片节奏、画幅、字幕安全区和交付要求；TalkCraft 按需提供分镜方法、动效卡、转场及配套音效。接入规则见 [talkcraft-integration.md](references/talkcraft-integration.md)。

## 执行方式

- 用户要求制作时，完成素材规划后继续制作；只有用户要求先选方向，或缺少影响结果的必要输入时才等待。用户明确要求优先于以下默认值。
- 先检查当前可用的转写、GPT Image、Remotion/Node.js 和 FFmpeg 能力；安装 Skill 本身不会安装这些运行工具。需要 TalkCraft 时检查所用文件和组件依赖，具体报错、修复结果及影响按接入说明告知用户，不静默跳过或替换。
- 连续生产、交付可编辑工程或处理磁盘占用时，先读取 [运行环境与清理策略](references/runtime-cleanup-policy.md)。优先复用版本匹配的共用运行环境，不在每条视频里重复安装同一套 Node、Python 和模型依赖。
- 优先使用用户提供的 B-roll；不足以表达时补充真实截图、图片或使用当前可用的 GPT Image 工具生图。生成画面用于解释或示意，不冒充真实产品界面、实测结果或真实案例。引用图片前取得可读的本地文件并放入工程媒体目录。无法取得文件时采用已有素材或代码动效，不为普通生图任务索要 API 密钥。

## 制作与交付

1. 检查已剪好口播，以真实音频建立画面与字幕时间线；文案和旧字幕只作语义参考。时间线与字幕断句按 [timeline-workflow.md](references/timeline-workflow.md)。
2. 按语义选择录屏、图片、动效或无素材过渡。素材选择、混合节奏和图片要求按 [asset-planning.md](references/asset-planning.md)。
3. 安排全片画面后，按 [TalkCraft 接入说明](references/talkcraft-integration.md) 为有必要的重点段落设计分镜与动效。真人可以独立承担一个段落，不强制逐句加素材、逐段加动效或固定动效比例。
4. 生成工程或编辑现有工程，执行 [remotion-rules.md](references/remotion-rules.md) 中的画面、字幕、编码与归档要求。只做规划时无需加载工程细节。
5. 检查最终产物，按 [quality-checks.md](references/quality-checks.md) 完成与本次交付有关的验收，修复实际发现的问题后交付。

## 默认交付约定

- `1080x1920 / 30fps / H.264` 高码率 MP4；视频目标 `8M`、`maxrate 10M`、`bufsize 20M`，AAC 音频至少 `128k`。复杂运动或录屏可用 `10M-12M`。用户指定其他规格时采用用户规格。
- 默认不额外加字幕，留出字幕区域；要求字幕时生成可编辑字幕数据，并按请求烧录。字幕、素材和真人口播以同一音频时间线为准。
- 真人 PIP 只使用原口播视频：开头与结尾默认各约 3 秒居中强化，正文位于中间下方，平滑移动并等比例裁切；具体安全区以工程配置为准。
- 默认交付 `final/` 成片、`images/` 实际使用图片和 `previews/` 验收图；生成字幕时另保留可编辑字幕数据。用户要求可编辑工程或剪辑师接手时，保留工程及所需素材。
- 验收完成后按 [运行环境与清理策略](references/runtime-cleanup-policy.md) 分阶段处理：立即清理 bundle、测试导出和验收中间视频；对能加速近期修改的分段缓存保留默认 7 天，必要时延长至 14 天；不随单条视频清理共用依赖、转写模型或系统工具缓存。
