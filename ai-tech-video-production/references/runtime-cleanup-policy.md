# 运行环境与清理策略

用于每周连续制作多条视频、交付可编辑工程和处理磁盘占用。目标是让每个项目只保存自己的内容，同时复用工具、依赖和模型；清理不能破坏近期修改能力或工程可恢复性。

## 四类文件

| 类别 | 典型内容 | 处理方式 |
|---|---|---|
| 项目长期保留 | 原口播、实际使用的 B-roll、工程源码、时间线、字幕、使用素材、最终成片、代表性验收图、依赖锁文件 | 不随清理删除 |
| 修改缓冲期 | 已渲染分段、最近一次可复用混音、能明显加速局部修改的缓存 | 成片确认后默认保留 7 天；近期经常修改可延长至 14 天 |
| 交付后立即清理 | `bundle-*`、失败或测试导出、低码率临时预览、全尺寸验收母版、分散抽帧、临时音频、未使用候选、已结束的预览或渲染进程 | 验收完成并回读交付物后清理 |
| 跨项目共用 | Node/Remotion 环境、Python 转写环境、Hugging Face 模型、包管理器缓存、FFmpeg、Chrome、字体、通用音效、TalkCraft/Video Use 等已安装 Skill | 不随单条视频清理；单独维护 |

包含词级时间戳、能支持字幕复核的 ASR JSON 不是草稿。将它整理为 `deliverables/subtitles/transcript-words.json` 或同等明确文件后长期保留；只删除转写临时 WAV、日志和已经被正式字幕数据取代的草稿。

## 共用运行环境

重复制作时优先使用一个稳定的共用环境，不在每个视频目录安装同一套依赖。推荐放在用户级数据目录，例如：

```text
~/.local/share/ai-tech-video-production/runtime/
  node/<依赖锁指纹>/
    package.json
    package-lock.json 或其他锁文件
    node_modules/
  python/<依赖锁指纹>/
    requirements.txt 或 pyproject.toml
    .venv/
```

- 只有 Node 版本、系统架构和依赖锁内容一致时才复用同一 Node 环境；版本不同时建立新的指纹目录，不直接覆盖旧环境。
- Python 环境同样按依赖清单区分。转写模型继续使用 Hugging Face 等工具的用户级模型缓存，不复制到每个项目。
- 每个项目仍保留自己的 `package.json`、锁文件和 Python 依赖清单，保证共用环境不可用或工程迁移时可以恢复。
- 项目可通过相对软链接或明确的运行脚本连接共用环境。创建链接前检查目标存在；交接说明写清共用环境路径，并提供从锁文件重新安装的回退方式。
- 没有可用共用环境时，使用包管理器的本地缓存恢复依赖；项目完成后可删除项目专用 `node_modules/` 和 `.venv/`，但不要因此清理全局下载缓存。

## 项目媒体只保留一份正式副本

原口播和 B-roll 在项目内应有唯一正式位置。不要为了让 Remotion 读取素材而把整个输入目录再复制一遍。

- 新项目优先采用一个 canonical media 目录，再从 `public/media/` 建立项目内相对链接；或只复制实际使用的素材。
- 在采用软链接、硬链接或文件系统克隆前，必须用真实的 Studio 预览和一次渲染验证路径、声音和打包结果。工程需要跨设备交接时，优先把实际使用素材实体化到交付工程。
- 不删除用户原始素材，也不让最终工程引用项目外即将清理的临时目录。

## 交付与修改缓冲期

1. 验收最终 MP4、字幕、代表性画面和工程引用，记录 `finalizedAt`。
2. 停止本任务启动的预览、浏览器和渲染进程。
3. 立即清理 bundle、测试导出、验收中间视频、分散抽帧和无用候选；保留必要验收报告和代表性 contact sheet。
4. 在项目记录中写明 `cleanupAfter`。默认是 `finalizedAt + 7 天`；近期修改频繁时使用 14 天，用户要求立即归档时可缩短。
5. 缓冲期内保留能支持局部重渲的 `out/` 分段和最近一次可复用混音。空间紧张时可以提前清理，但必须说明下次修改将需要整片重渲。
6. 到期后确认项目没有进行中的修改，再清理分段缓存和项目专用依赖；保留长期文件。统计并报告清理前后占用。

清理仅针对已经确认属于当前任务且可重建的路径。未知目录、其他任务、仍在使用的运行环境和验收失败现场不处理。需要实际释放磁盘时，移入废纸篓后还要说明空间尚未释放；永久删除前再次核对精确目标。

## 系统缓存维护

系统缓存不属于某条视频，不能在每次交付时顺手清理。每月一次，或磁盘可用空间低于总容量 10% 与 40GB 中较大者时，单独执行缓存盘点：

- npm：优先验证缓存并清理长期不用的 `_npx` 工作目录；不要把 `npm cache clean --force` 当成日常步骤。
- uv：使用 `uv cache prune` 清理不可达对象，不直接删除整个缓存目录。
- Hugging Face：保留当前转写流程实际使用的模型；只有确认没有 Skill、脚本或在办项目引用时才移除旧模型。
- Playwright 或浏览器缓存：按实际安装版本和其他自动化任务审计，不由视频项目清理流程直接处理。

缓存维护开始前记录各目录大小和磁盘剩余空间，结束后重新统计。不要因为目录大就假定它属于当前视频。
