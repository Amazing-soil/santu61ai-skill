# 整理与剪辑方法

## 原片与选段分开登记

建立新批次目录，原片只读。用户口述活动日期与拍摄时间可能不同，两者保留并核对。清单记录真实文件名、时长、尺寸、旋转、帧率、色彩、音轨、SHA256、人物与外发限制。

`scripts/inspect_media.py`生成技术清单；人物、内容、声音是否清楚及允许外发仍结合资料与原片判断。抽帧不代替了解叙事，转写不代替核听。候选计划参考[剪辑计划示例](../assets/剪辑计划示例.json)。

| 项目 | 留下什么 |
|---|---|
| 来源 | 文件名、原片SHA256、粗剪编号与对应原片区间 |
| 时间码 | 原片起止秒数；再次裁粗剪时另记粗剪自身时间 |
| 主题 | 具体讲什么，前提、过程、例子及结论是否齐全 |
| 声音 | 谁发言，是否清楚，有无漏句、无麦或远距离问题 |
| 画面 | 人物、构图、动作与禁用人物检查 |
| 用途 | 中长主题／完整短视频／过程展示／混剪备用／内部留档／去掉 |
| 账号 | 品牌、允许的同源复用、关联成片及状态 |

已给其他账号使用的区间单独标记，不能换编号再分配。缺少人物关系时列待核对，不能猜身份、只按衣服颜色认人或将禁用人物带入群像。

## 先看完整表达，再决定长度

优先围绕一个问题、一件事或一次示范的中长主题。保留理解所需的前提、人物回应、例子与结论，可去准备动作、无价值停顿和离题，不为片长省掉推理的关键一步。

不能做中长，但完整讲了一段经历、一件事、一次判断或方法的，可做完整短视频。只有一句完整有价值的话也可独立交付，不能将各自残缺的句子冒充故事。同一人物分散录制的片段，只有事件、上下文和顺序能核对时才衔接，不拼出新观点或虚构练习前后对比。

## 声音决定能否做原声作品

逐个主要发言人检查。主持人很响、客户没戴麦时，整体响度正常不表示客户的话可听清。字幕不能代替清楚原声，不能大幅增益放大噪声后称为清晰。

主要讲话听不清：不做独立原声中长或短片；可用画面去原声列混剪备用。只有得到修复授权且实际证明能听清后，才重新评估用途。ASR成功、音轨存在和解码通过均不是听清证据。

## 其他用途

| 用途 | 方法 |
|---|---|
| 路演打磨 | 试讲→点评→指导修改，去原声跳剪，用配乐和阶段字呈现真实过程，通常12—18秒 |
| 两三句原声跳剪 | 完整句及必要前后文，原意和语境不变 |
| 多人自我介绍 | 按真实次序，单人介绍与合集分别登记，姓名采用确认称呼 |
| 现场介绍与口号 | 按任务留完整开头、介绍首句与场景；口号从真正起声处留全句，预估秒数需核听 |
| 独立无声场景 | 静音底片只作来源，成片加主题与可闻音轨 |
| 极短混剪 | 剩余可用区间选7—10秒，镜头长短交替、自然互动收尾，参考M01 |
| 其他现场混剪 | 优先15—20秒，不为数量慢放、冻结或重复 |

无声混剪批次尽量包含纯现场、现场＋单人、单人混剪；按实际素材分配，不定固定比例。禁用人物不能出现在任何组合中。

## 样片、批量与交付

先交分类与计划，每类一条样片确认后批量。用户已确认同样风格且授权继续时执行该范围；素材不足就少做，不将固定数量当验收指标。

原声字幕配时间戳，长句按自然半句依次显示，不留孤立词尾。首帧封面、底部说明、品牌双色、字幕、大字阶段、原声与BGM分别核对。交付独立文件和可播放目录，不仅交检查缩略图。

保存选段、来源、字幕、配乐区间、字体来源、工程依赖及检查范围。新电脑的素材路径放配置中，工程优先相对路径，不写死原机用户名或挂载点。样例编号、日期、数量、曲目和文案不是下批常量。
