# 颜色与轻美颜

原始手机文件、正确SDR底片、美颜画面和参数分别保存，不覆盖原片。先确认颜色与亮度，再比较美颜；不能用额外提亮掩盖错误HDR转换。

## HDR到BT709 SDR

读取ffprobe的transfer、primaries、matrix、旋转及Dolby Vision信息。`arib-std-b67`、`smpte2084`和DOVI提示需检查HDR流程。只把标签写成BT709不是色调映射。

本系列在Apple Silicon macOS验证过Apple AVFoundation路线：VideoComposition的primaries、transfer、matrix设为BT709，使用Apple 1920×1080导出预设处理preferredTransform；随后只归一化到30fps，不再做第二次tone map，不额外提亮。横竖方向从实际输出核对。

包内携带源代码`apple_sdr_export.m`及`apple_sdr_cli.py`。前者需在目标Mac编译，后者从PATH或显式参数找FFmpeg/ffprobe，不含原机的可执行文件。编译与调用见[新电脑运行](新电脑运行.md)。

在同人物、白墙、投屏和暗部的相同时刻，与Apple正常SDR观看参考核对。编译通过、标签正确、画面可解码都不代表视觉已经一致。

Windows/Linux不能运行AVFoundation。可使用当前环境可用的HDR→SDR方法，但需先做短样片并与正确SDR参考对照；方法改变或效果不确定时说明，不能静默改为额外提亮、重复tone map或宣称与Apple完全一致。没有合适工具时先完成分类与时间码，保留原片。

## GPUPixel单人近景

已确认参数：磨皮0.22、美白0、锐化0.08；单人近景开启，多人远景和空间保持基础画面。不瘦脸、不大眼。

使用GPUPixel的`BeautyFaceFilter`，`SetBlurAlpha(0.22)`、`SetWhite(0)`、`SetSharpen(0.08)`。包内`gpupixel_stream.cc`读取标准输入的整帧RGBA，输出同尺寸RGBA，参数包含宽、高和本机资源目录；诊断文字写入stderr，不能混入像素流。

实际处理顺序：BT709 SDR底片→FFmpeg解码RGBA→gpupixel_stream→FFmpeg编码视频→从底片复制原音轨。确认RGB全范围与最终视频有限范围的转换，H.264/AAC、BT709标签、帧数和时长正确。音轨要求保持时用copy并核对音频包哈希。

运行参数：

```text
gpupixel_stream <宽> <高> 0.22 0 0.08 <本机GPUPixel资源目录>
```

GPUPixel运行库、资源和编译产物另行准备，不能把另一台Mac的二进制当跨平台安装包。本机可用、GPU权限正常后先做10—15秒同源对照，查看头发、眼镜、皮肤、衣服、背景字、转头和手势。

桥接源码在GPUPixel提交`ef552bf8ce2d0d41fa9b979bfb5c7cf79374ca88`的头文件和静态库上编译验证。资源根目录下须有`res/lookup_gray.png`、`lookup_origin.png`、`lookup_skin.png`及`lookup_light.png`，运行前检查实际可读。归档后指向未连接共享盘的资源软链接会让GPU程序失败；新电脑准备真实本地资源，不能只复制链接。上游版本变化时重新核对API和资源。

缺少GPUPixel时如实说明，继续其他可独立工作；关闭美颜可复制底片保持字节一致。FFmpeg全画面降噪/LUT仅是另一种处理，不称为人脸专用磨皮，不无声替换已确认方法。生成式图片或视频工具不用于替换真实人物画面。
