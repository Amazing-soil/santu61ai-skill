# 本地音频素材同步

用户要求换电脑继续剪辑并同步本地音频时，音频是配套交付的一部分，不能只同步Skill文字、文件名或原电脑软链接。

本系列已登记30首：激动亢奋18首、平静舒缓7首、情绪画外音5首。目录见[曲目索引](../assets/audio/曲目索引.json)，包括编号、真实文件名、SHA256、主题、推荐区间、原始响度与声音分析范围。实际音频独立保存，索引存在不表示音频已下载或已同步。

## 同步什么

- 30首原始音频，保持原文件名、目录层级与曲目编号，不用重编码代替原文件。
- 曲目索引、已有来源与许可记录。人声文案、字幕、选段说明若用于继续制作，一起放入私有素材目录；机器转写与人工核听状态保持区分。
- 每条成片使用的曲目编号、起止秒数、增益、淡入淡出和是否含人声，保存在本条工程。原始LUFS不是固定混音音量，M01使用BGM-003的12—22秒、0.55增益只是实例。

## 实际文件和路径

先检查本机BGM目录。若文件是共享盘软链接，确认共享盘已挂载，完整读取目标文件；不要把链接文件本身上传或复制后称为音频齐备。

在目标电脑将真实音频放同一个素材根目录，工程中以素材根目录＋索引相对路径引用，不能写死原机用户名、盘符或共享盘挂载点。克隆私有素材仓库、连接共享盘或从本机已有素材复制均可，按用户确定的目标执行，不自动创建外部仓库。

逐文件完整校验SHA256，核对30个索引对应真实音频。缺少、断链、内容不一致就列待补，不自动换曲、换成网络同名文件或冒称同步完成。Git单文件限制、实际总大小和目标私有可见性应在传输前检查。

## 公开Skill与私有音频

当前Skill仓库是公开仓库。可公开同步方法和曲目目录；音频原文件、许可凭证及内部人声资料按用户确定的私有范围处理，不默认与Skill一起公开发布。

其中10首来自Pixabay，其[许可摘要](https://pixabay.com/service/license-summary/)禁止将内容未经创作改变、保持基本原样地独立销售或分发；用于剪辑不等于可公开提供原曲下载。另外20首为用户提供，现有索引的来源链接和许可记录尚未补齐。保留事实状态，不宣称全部有公开再分发授权，也不把音乐许可误当作Skill代码的MIT许可。

用户选择私有云端仓库后，先核对账号、目标仓库和私有可见性，再上传音频及来源资料。公开Skill只记录仓库位置或本机配置方式，访问凭据留在当前电脑，不写入代码或文档。

## 清理下载目录中的重复音频

只有在用户授权清理后，才检查其指定下载目录。按内容SHA256匹配，允许下载时的文件名与素材库文件名不同；文件名相同不代表内容相同。

匹配后还要完整回读共享盘上的实际文件，核对两端SHA256和大小，确认核验期间没有变化，并持久保存来源、目标、曲目编号和校验结果。通过后只清理本地重复副本，保留共享盘原文件和曲目索引；未匹配、源不可读、目标不可读或内容不一致的保留。

清理结果写出具体文件数、文件合计容量和保留项。不能把移到废纸篓的容量直接称为磁盘已释放，也不能顺便清理项目缓存、原始现场录音或其他目录。

## 本系列私有音频库

用户确定的私有仓库：[Amazing-soil/salon-audio-assets](https://github.com/Amazing-soil/salon-audio-assets)。只有有权限的账号能够克隆或下载，不将凭据写入Skill。目录中的`BGM/曲目索引.json`保留本系列原始索引，`文件校验.json`和`verify_library.py`用于检查实际文件。

新电脑登录自己的GitHub账号后，在选定素材目录执行：

```text
gh repo clone Amazing-soil/salon-audio-assets
python salon-audio-assets/verify_library.py
```

将`salon-audio-assets/BGM`作为本机音频素材根目录，用曲目索引的相对路径寻找实际音频。没有GitHub CLI时也可用已有Git认证克隆该私有仓库；需要登录时由用户在本机完成，不索取或复制其他电脑的凭据。校验未通过前不称为音频齐备。
